# Daily Loop — 도메인 모델

> `project-spec.md`, `user-flow.md`에서 확정된 내용을 기반으로 한 엔티티/관계/비즈니스 규칙 정리. DB 컬럼 타입 등 구현 상세는 `erd.md` 참고.

---

## 1. 엔티티 개요

| 엔티티 | 한 줄 설명 |
|---|---|
| User | 로그인한 사용자 |
| Slot | 사용자별 4개 고정 시간대 (아침/점심/저녁/자기전) |
| Category | 루틴/영상 공용 카테고리 (6개 고정) |
| Video | 큐레이션된 유튜브 영상 |
| Routine | 사용자가 만든 루틴 블록 (반복 규칙 포함) |
| RoutineCompletion | 특정 날짜에 루틴을 수행한 기록 |
| Diary | 날짜별 일기 (텍스트) |
| StreakEmojiConfig | 연속 성공 일수 구간별 이모지 설정값 |

---

## 2. 엔티티 상세

### 2-1. User

- 소셜 로그인(구글/카카오)으로만 생성됨. 이메일/비밀번호 자체 가입 없음
- 가입 시 4개 Slot이 기본값으로 자동 생성됨 (1:1로 안 됨 — 정확히는 1:4)
- LLM 호출 누적 횟수를 보유 (무료 버전 계정당 총 10회 상한, 4-13 참고)

**속성**: 식별자, 이메일, 인증 제공자(google/kakao), LLM 누적 호출 횟수, 가입일시

---

### 2-2. Slot

- 사용자당 정확히 4개 (아침/점심/저녁/자기전) — 개수 자체는 커스텀 불가
- 시작/종료 시각은 사용자가 설정 화면에서 조정 가능
- 슬롯 단위 알림 on/off 보유 (개별 Routine의 알림 토글과는 별개 개념)
- Routine이 "시각 대신 슬롯"으로 배정될 때 참조되는 대상

**속성**: 식별자, 소속 User, 슬롯 종류(고정 4종 중 1), 시작 시각, 종료 시각, 알림 on/off

**규칙**: `(User, 슬롯 종류)` 조합은 유일해야 함 — 한 유저가 "아침" 슬롯을 2개 가질 수 없음

---

### 2-3. Category

- 6개로 고정: 운동 / 뷰티 / 독서 / 모닝루틴 / 마인드풀니스 / 공부·자기계발
- Routine과 Video 양쪽에서 공용으로 참조 (사용자가 새 카테고리를 만들 수 없음 — 시드 데이터)

**속성**: 식별자, 이름

---

### 2-4. Video

- 직접 제작 없이 기존 유튜브 영상을 큐레이션 (임베드 방식)
- 반드시 채널명 + 채널 링크를 함께 보유해야 함 (저작권 정책 준수, 6번 참고)
- 정확히 1개 Category에 속함

**속성**: 식별자, 소속 Category, 제목, 유튜브 URL, 썸네일 URL, 채널명, 채널 링크

---

### 2-5. Routine (핵심 엔티티)

사용자가 만든 루틴 블록. 반복 규칙 + 완료 방식 + 배치 방식을 모두 가짐.

**속성**:
- 식별자, 소속 User, 제목
- 타입: 일반형(체크) / 트래킹형(수치) — 4-6
- 반복 규칙: 매일 / 특정 요일 조합 / 평일만 / 주말만 / 1회성
- 배치 방식: **정확한 시각** 또는 **슬롯 참조** 중 반드시 하나 (동시에 둘 다는 불가 — user-flow 3번에서 확정)
- 필수/선택 여부 (필수 미완료 시 캘린더 빨간 표시의 판단 기준, 4-4)
- 알림 on/off (이 루틴 하나에 대한 개별 알림 — Slot 알림과 별개)
- 소속 Category (선택)
- 연결된 Video (선택)
- 단위 (트래킹형에만 해당 — 프리셋 또는 자유 텍스트, 4-6)
- 정렬 순서값 (같은 시각/슬롯 내 사용자 지정 순서, 4-7)
- 생성일시, 삭제일시(소프트 삭제, 3-2)

**규칙**:
- 트래킹형은 목표치 대비 달성/미달성을 판정하지 않음 — 값이 입력되는 순간 그날은 "완료"
- 소프트 삭제된 Routine은 목록/체크에서 제외되지만, 과거 RoutineCompletion 기록은 그대로 유지 (통계 정합성 보존)
- 필수 Routine이 그날 RoutineCompletion을 갖지 못하면 → 그날 캘린더 표시가 빨강으로 판정됨

---

### 2-6. RoutineCompletion

- 특정 Routine이 특정 날짜에 수행되었다는 기록. 하루당 최대 1건
- 일반형은 값 없이 "완료 시각"만 의미 있음, 트래킹형은 입력값(숫자)이 통계용 원시 데이터로 저장됨

**속성**: 식별자, 소속 Routine, 날짜, 값(트래킹형만), 완료 시각

**규칙**:
- `(Routine, 날짜)` 조합은 유일 — 하루에 같은 루틴을 두 번 완료 처리할 수 없음(재탭 시 취소/수정으로 처리)
- **과거 날짜(오늘 이전)의 레코드는 생성/수정/삭제 불가** (앱 로직에서 차단, DB 제약은 아님) — 캘린더에서 과거 체크리스트는 읽기 전용으로 확정

---

### 2-7. Diary

- 날짜당 정확히 1개. 텍스트만 지원 (사진 등 첨부 없음, 4-5)
- 캘린더에서 날짜 클릭 시 그날의 RoutineCompletion들과 함께 조회됨 (직접적인 FK 관계는 아니고 날짜로 묶여서 조회)

**속성**: 식별자, 소속 User, 날짜, 내용, 작성일시, 수정일시, 삭제일시(소프트 삭제)

**규칙**: `(User, 날짜)` 조합은 유일

---

### 2-8. StreakEmojiConfig

- "같은 루틴을 연속 며칠 성공했는가"를 이모지로 표시하기 위한 구간 설정값 (4-11)
- 사용자별이 아니라 **앱 전역 설정** — 운영자가 나중에 구간/이모지를 조정할 수 있도록 테이블로 관리

**속성**: 식별자, 최소 연속일수, 최대 연속일수(마지막 구간은 상한 없음), 이모지, 구간 이름

**연속일수 계산 규칙**: 특정 Routine에 대해 오늘 기준으로 RoutineCompletion이 끊기지 않고 이어진 일수를 계산 (반복 규칙상 "쉬는 날"은 연속 카운트에서 제외 — 예: 평일만 반복이면 주말은 카운트 공백으로 보지 않음)

**날짜 경계 기준 (신규 확정)**: 하루의 기준은 **자정(00:00)**. "자기전" 슬롯이 새벽까지 이어지더라도(예: 21:00–05:00) 스트릭/통계/캘린더가 참조하는 "그날"은 자정에 넘어감 — 슬롯 시간 범위는 어디까지나 알림·정렬용이고, 날짜 판정 로직과는 분리됨

---

## 3. 관계 요약

```
User 1 ── 4 Slot                (가입 시 자동 생성, 정확히 4개)
User 1 ── N Routine
User 1 ── N Diary
Slot  1 ── N Routine             (Routine이 시각 대신 슬롯 배정을 선택한 경우만)
Category 1 ── N Routine          (선택적)
Category 1 ── N Video
Video 1 ── N Routine             (하나의 영상을 여러 루틴이 연결 가능, 선택적)
Routine 1 ── N RoutineCompletion
```

- `StreakEmojiConfig`는 다른 엔티티와 FK 관계 없음 (전역 참조 데이터, 연속일수 계산 로직에서 조회만 함)
